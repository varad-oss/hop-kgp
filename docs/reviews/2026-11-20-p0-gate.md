### Next tier (each real, none blocks submission)

- **Forged cards crash or spoof the room.** Lobby and pod render `Hop:*` custom messages from any sender (`l/[lobbyId]/page.tsx:196-205`, `pod/[podId]/page.tsx:58-61`) and the webhook only checks `RC:TxtMsg`. A lobby member who sends a `Hop:Proposal` with `vehicle: "x"` makes `VEHICLES[proposal.vehicle].label` throw at `components/cards.tsx:76` and blanks the lobby for everyone (no error boundary). A pod member can post a fake `Hop:Ticket` with wrong fares or numbers (`cards.tsx:170,194`). Fix: only render proposals whose id is in the DB summary using DB fields, only accept tickets whose `senderId` is the bot, add an error boundary. 30 min.
- **One-tap phone disclosure link.** `/l/<lobby>?join=<lockedProposalId>` auto-joins on page load for anyone with an intent in that lobby and a saved profile (`l/[lobbyId]/page.tsx:95-103`), which reveals their number to a pod of strangers. Require a confirm tap when `?join=` is present. 15 min.
- **ICS injection.** `meetingPoint` is trimmed but may contain CR/LF; `domain/ics.ts:17` writes it raw into `LOCATION:`, so a malicious proposer can append `URL:`/`ATTACH:`/alarm lines to a victim's calendar file. Strip control characters server-side (`proposals.ts:45-47`) and escape `, ; \` in the ICS. 10 min.
- **Rate limits only on token, intents, proposals, demo, feedback, events.** Join/leave/lock, `/api/lobbies/*/summary`, `/api/pods/*`, `/api/me/profile` and `/api/demo/leave` have none, and each join/leave triggers 1-3 Nexconn calls. Anonymous Supabase sessions are free, so one script can burn Nexconn quota or the 10K MAU / ~500 PCC allowance (anon sign-ins are the only IP-limited step, by Supabase defaults). Add `hitRateLimit` to those routes (20/min per user) and turn on Supabase CAPTCHA for anonymous sign-ins if time allows. 20 min.
- **Webhook hardening.** `verifyWebhook` (`server/webhook.ts:4-7`) has no timestamp window (replayable), a non-constant-time compare, and if `NEXCONN_APP_SECRET` were ever unset it validates against an empty secret (anyone could sign). Reject empty secret, check |now - Timestamp| < 5 min, use `timingSafeEqual`. 10 min.
- **Lock after departure.** `lock_proposal` has no `p_now >= depart_at` check (join does), so a stale plan can be locked after it left. 5 min inside the 0003 migration.
- **Display-level privacy.** `/api/lobbies/:id/summary` returns every intent's name, hall and Nexconn id to any signed-in real user who knows a lobby UUID, member or not (`server/lobbies.ts:141-191`). Acceptable for a community lobby; either gate it to members or say so in the privacy page.
- **Past trips pile up** in "Your trips" forever (no date filter in `listMyTrips`). 10 min.
- **Local hygiene:** `chmod 600 web/.env.local`; pull `VERCEL_OIDC_TOKEN` out if you share the machine.

### Things I checked and found sound

Token issuance is server-only with per-user rate limit (10/min); the App Secret is not in any client bundle. Authorization on every non-public route is correct: proposals go through `proposalAndLobby` + `assertCanSee`, pods require an `in` membership row (404 otherwise), feedback requires membership, demo and real lobbies are mutually invisible, `/p/<id>` shows counts only and returns nothing for demo plans. Join, leave and lock each `select ... for update` the proposal row, so seat caps and "one vote per proposal" hold under concurrent taps (single-proposal races are fine; only the cross-proposal case in #7 breaks). Lock-time Nexconn failure is handled by design (see #8). XSS: no `dangerouslySetInnerHTML` anywhere, React escapes all card text, `tel:` links use a stored 10-digit string, share uses `wa.me` with encoded text. CSRF is covered by Supabase's `SameSite=Lax` cookies (no explicit Origin check; mention if you want to be tidy). Webhook signature scheme is right (SHA1 of secret+nonce+timestamp); a bad signature gets 401. Timezones are handled in IST regardless of device locale. Atomic functions are tested.
